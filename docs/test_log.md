### 입력 처리에서 발견한 것
| 문제 | 내용 | 대응 |
|---|---|---|
| 본문이 글자가 아니라 이미지 | PPT를 PDF로 저장할 때 폰트를 못 넣어 글자를 이미지 조각으로 바꿈 (페이지당 최대 194개). 텍스트 추출 시 33장 전체에서 1,613자만 나옴 | 페이지를 이미지로 렌더링(pypdfium2) → AI가 페이지 이미지를 직접 읽음 |
| 옛한글 | 향가 해독문(아래아 등)은 이미지에서 옮긴 글자라 오인식 가능성 있음 | 해당 표에 "원본 대조 필요" 표시 |
| 이미지 슬라이드 | 지도·사진·그림(p.16, p.18) | [이미지] 설명으로 대체 |
| 빨간색 강조 | 원본에서 핵심어를 빨간색으로 강조 | 검정 기준 규칙에 맞춰 **굵게**로 변환 |
| 같은 내용의 표기 차이 | p.10과 p.11 표의 연대·작품명이 다름 (도천수대비가/도천수관음가 등) | 고치지 않고 원본 그대로 + 차이 메모 |

### 서비스 설계에 반영할 것
- **PDF 입력은 "텍스트 추출 → 실패하면 페이지 이미지 읽기" 두 단계가 기본**이어야 한다 (학교 PPT PDF는 이미지 글자가 흔할 수 있음)
- 텍스트가 거의 없는 페이지 비율로 자동 판별 가능 (이번: 33장 중 30장 이상이 100자 미만)
- 옛한글·한자 많은 자료(A 유형)는 인식 불확실 구간 표시가 필요

### 입력 처리에서 발견한 것
| 문제 | 내용 | 대응 |
|---|---|---|

| 그래프·그림 | 누적분포 계단 그래프, 결합분포 3D 그림 등 | [그래프]/[그림] 한 줄 설명 |

- 표 셀의 분수는 `1/8` 텍스트로 (표 안 LaTeX는 렌더러마다 깨짐)
- 마지막 요약은 **공식표(이산형/연속형 비교) + 예제 지도** 두 개

## T5. 누락 점검 단계 (2026-10-15)

- `app/engine.py` `check_omissions` + `apply_omissions`: 생성 후 PDF와 노트를 다시 대조 → 빠진 내용을 JSON(쪽, 설명, 앞 줄, 넣을 마크다운)으로 받아 노트에 끼워 넣음. 자리를 못 찾으면 맨 끝 "누락 점검으로 보충한 내용" 절
- 기계 대조 `text_layer_gaps`: 텍스트 레이어의 한자 덩어리(8자 이상)가 노트에 없으면 모델에게 힌트로 전달
- 생성 프롬프트에 "빠뜨리기 쉬운 요소"(한자 원문·출전·캡션 등) 추가
- 4강 자동 노트 점검: **0건**, 입력 73,362 / 출력 445 토큰, $0.30 → 점검 1회 비용은 생성의 약 1/3
- 기계 대조 오탐: 4강 p.28 "遇賊歌 口口口 寸金" (원본 빈 네모 □가 텍스트 레이어에서 '口'로 나옴) → 모델이 이미지로 확인하므로 허용
- 비교 스크립트(`compare_notes.py`)의 "못 찾은 줄"은 줄 단위라 줄을 합치면 오탐 → 누락 판단에 단독으로 쓰지 않음
