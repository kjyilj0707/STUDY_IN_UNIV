## 3. 수업계획서로 유형을 판정하는 기준 (가설)

| 신호 (수업계획서에서) | A 서술·해석 | B 수리·계산 | C 개념·사례 | D 코딩·실습 | E 과제·프로젝트 |
|---|---|---|---|---|---|
| 학문 분야 | 문학·사학·철학·언어 | 통계·수학·공학·회계 | 경영·경제·사회과학 | 프로그래밍 | 무관 |
| 수업 자료 성격 | 작품 원문, 사상가 텍스트 | 수식, 예제 | 사례(케이스), 용어 | 코드 | 템플릿, 참고 논문 |
| 시험 형식 | 서술형·논술형 | 계산·풀이 | 객관식·단답 | 실기·코드 작성 | 시험 비중 낮음 |

- 한 과목에 유형이 둘 붙을 수 있다 (주 유형 + E). 예: 국문학개론 = A + E
- 판정할 때는 근거 문장(수업계획서의 어느 부분)을 같이 보여주고, 사용자가 고칠 수 있게 한다

- **주차별 수업 일정표** → 강의자료를 주차에 자동 연결하고, 시험 범위(예: 중간 = 1~7주)를 자동으로 잡을 수 있음

**서비스 설계에 영향을 주는 발견**
- 국문학개론 수업계획서에 **"담당교수 승인 없는 강의 녹음·유출은 부적절, 배포·상업적 활용은 형사처벌 대상"**이라고 명시돼 있다.
  → 녹음·스크립트 입력은 "본인 학습용, 공유 불가"로 제한하고, 업로드할 때 교수 승인 여부를 확인하는 안내가 필요하다. 원래 아이디어의 "수업 녹음" 기능은 이 문제를 먼저 풀어야 한다.
- 동양철학의 세계 수업계획서의 강의 진행 방식 표에 **"전면금지(Totally banned)"** 항목이 있다 (설명 칸은 비어 있음). 위치로 보아 **생성형 AI 활용 정책**일 가능성이 크지만 확인이 필요하다.
  → 맞다면 수업계획서에서 **AI 사용 정책(전면허용/부분허용/전면금지)**을 읽어서, 금지 과목에서는 과제(E) 관련 기능을 끄고 안내를 띄워야 한다.
- **학교 포털 PDF는 일반 PDF 도구로 한글이 깨진다** (한글 폰트 미내장, UCS-2 저장). `scripts/extract_syllabus_pdf.py`로 해결했다. 서비스의 수업계획서 업로드도 같은 처리가 필요하다.

## 4. MVP에 넣을 유형 추천

1. **A. 서술·해석형** — 근거 대화가 가장 많고 (24개), 1단계(강의 노트) 작업이 주차마다 똑같이 반복돼서 자동화 효과가 크다
2. **B. 수리·계산형** — 파이프라인이 가장 뚜렷하고 (정리 → 유도 → 문제집 → 실전), 문제 생성의 가치가 크다 (근거: 통계 17 + 회계 3)
3. (여유 있으면) **C. 개념·사례 이해형** — 대화는 많지만(17개) 시험 형식 정보가 부족하다

D와 E는 MVP 이후로 미룬다. D는 코드 실행 확인이 필요하고, E는 대리 작성 문제가 있다.
